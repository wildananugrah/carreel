System architecture

End-to-end flow from recording to Gemini analysis with TF.js hints

Data flow — recording session → Gemini job

→

→

+

{ timestampSec, bbox%, class, score } accumulated in ref during recording
② SUBMIT PHASE — after driver taps "Selesai"

Existing flow unchanged
→

→

③ ANALYSIS PHASE — background job

Reads hints from step, appends to Gemini prompt
→
buildBodyInspectionPrompt
Injects hint timestamps into system instruction section
→
Gemini analyzeVideo
Gets roadmap of suspicious timestamps, produces definitive damage list
→
WebSocket notify
Existing flow unchanged
Model serving

EfficientDet-lite0 model files (~4.4 MB) live in driver-app/frontend/public/models/efficientdet-lite0/. Loaded lazily when BODY_INSPECTION recording starts, cached by browser service worker after first load. Swappable — replace files to upgrade the model without a code change.

Graceful degradation

If TF.js fails to load, WebGL unavailable, or inference is too slow (<200ms budget exceeded), the detection silently turns off. Recording and Gemini analysis continue normally — the feature is additive, never blocking.
